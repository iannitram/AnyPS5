# libc technical debt

### Unknown function info

- [fdopen](../../../core/libs/prx/libc/src/FileAndHeap.cpp) (libc) validates descriptor access modes as FreeBSD 11.4 [fdopen.c](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libc/stdio/fdopen.c) does: a requested mode incompatible with a descriptor not opened for both reading and writing returns null with `EINVAL`, leaving the descriptor open. Windows reads the handle's granted access through the same host helper as `fcntl(F_GETFL)`; a closed descriptor returns null with `EBADF`. Console behavior is unverified.
- [scriptingGetMem, scriptingFreeMem](../../../core/libs/prx/libc/src/ApplicationHeap.cpp) (libc) - runtime allocator hooks for Unity titles. The allocation signature `(alignment, size)`, minimum alignment 16 and null result for a non-power-of-two alignment follow [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/df5b9b92be7dfd463b47756b707d6d356a9f0550/src/libs/libKernel.cpp); the free hook's one-pointer signature follows [Raeen's recorded contract](https://github.com/Whoisraeen/Raeen/blob/2db56923204b89719916b95e29c2f3c4e1d9f90b/docs/unity-dlsym-blocker.md). Both use the registered application allocator. No console measurement; null allocation returns null and other allocator errors throw.

- [_Mtx_trylock](../../../core/libs/prx/libc/src/Threads.cpp) (libc, NID `k6pGNMwJB08`) - returns busy for a non-recursive mutex already owned by the caller, assumed to match `_Mtx_lock`'s ownership handling; exact console behavior is unverified.
- [nearbyintf](../../../core/libs/prx/libc/src/Math.cpp) (libc, NID `c+4r-T-tEIc`) uses the host rounding mode, not the console's; console rounding mode state remains unverified.
- [_Thrd_sleep](../../../core/libs/prx/libc/src/Threads.cpp) (libc, NID `jfRI3snge3o`) follows the Dinkumware threads library shipped with [Visual C++ 2013](https://github.com/adityaramesh/concurrency_runtime/tree/master/VS2013_SP2/crt/src/thr) (`xtime.c`) and C11 Annex K, without console verification. It reads a 16-byte xtime (64-bit seconds and nanoseconds) on the guest `CLOCK_REALTIME`, normalizes the nanoseconds and sleeps through `nanosleep`, retrying on `EINTR`, so it is a cancellation point; a null xtime or one whose normalization overflows throws. The console's `_Thrd_sleep` (disassembled from a title's `libc.prx`) also takes an optional `xtime*` of remaining time and returns `int`; here the sleep is never cut short, so it returns 0 and leaves the remaining time untouched.
- [_Mtx_init_with_name](../../../core/libs/prx/libc/src/Threads.cpp) (libc, NID `tgioGpKtmbE`) forwards to `_Mtx_init` and ignores the mutex name parameter.
- [_Cnd_timedwait](../../../core/libs/prx/libc/src/Threads.cpp) (libc, NID `McaImWKXong`) follows the console's `_Cnd_timedwait` (disassembled from a title's `libc.prx`), where xtime is an absolute deadline converted against the current time: it returns `_Thrd_timedout` (2) on expiration and `_Thrd_success` (0) on notification. The console returns 4 for other internal pthread errors while this implementation throws.

- [malloc_usable_size](../../../core/libs/prx/libc/src/ApplicationHeap.cpp) (libc) - with the default allocator it returns the size the block was requested with (the range registered for it), not the rounded-up chunk size Sony's allocator reports; both satisfy "at least the requested size", and bytes past the request would not be write-watched. - [malloc, calloc, realloc, memalign, aligned_alloc and reallocalign](../../../core/libs/prx/libc/src/FileAndHeap.cpp) (libc) - follow FreeBSD 11.4 `contrib/jemalloc/src/jemalloc.c` for failures, not measured on the console: a size the default heap rejects or the guest arena cannot place (including a `calloc` product that overflows) returns null with `errno` `ENOMEM`, and `memalign` and `aligned_alloc` return null with `EINVAL` for an alignment that is zero or not a power of two. FreeBSD's libc has no `memalign`, so setting `errno` there is assumed. A host commit failure for a block that fits in the arena (Windows `ERROR_NOT_ENOUGH_MEMORY`, `ERROR_OUTOFMEMORY` or `ERROR_COMMITMENT_LIMIT`, Linux `ENOMEM`) resets and releases the reserved range and returns null with `ENOMEM`; any other commit failure releases the range and throws. `reallocalign` returns null with `EINVAL` for an invalid alignment and `ENOMEM` like the others, which is an assumption as it is not in FreeBSD. `realloc(ptr, 0)` frees the block and returns null, where FreeBSD 11.4's jemalloc 4.5 resizes it to one byte and returns a block
- [reallocf](../../../core/libs/prx/libc/src/FileAndHeap.cpp) (libSceLibcInternal, implemented in libc) - follows FreeBSD 11 `lib/libc/stdlib/reallocf.c` on top of this libc's `realloc`, not measured on the console: size 0 frees the block and returns null as `realloc` does here, so the block is not freed twice; when `realloc` fails because the application allocator returns null or the default heap rejects the size, the block is freed through the same allocator, `errno` is `ENOMEM` and null is returned. Other failures (a commit failure that is not out of memory, an unknown pointer) throw, as they do for `realloc`

- [random, srandom, initstate, setstate](../../../core/libs/prx/libc/src/Random.cpp) (libc) follow FreeBSD 11 [random.c](https://github.com/freebsd/freebsd-src/blob/4ab2e064d7950be84256d671a7ae93f87cc6aa36/lib/libc/stdlib/random.c): the additive feedback generator on a default 128-byte `TYPE_3` table, `good_rand` seeding, state sizes rounded down to 8, 32, 64, 128 or 256 bytes, and `setstate` returning the previous state or null for a rear position past the degree. `initstate` below 8 bytes returns null without setting errno, as that file and its manual do (glibc sets `EINVAL`). ### Functional

- [__isfinitel](../../../core/libs/prx/libc/src/Math.cpp) - classifies the x87 80-bit exponent without narrowing to double or performing floating-point comparisons, following [FreeBSD msun](https://github.com/freebsd/freebsd-src/blob/main/lib/msun/src/s_isfinite.c). The signature and classification follow FreeBSD; console behaviour is unmeasured. Requires little-endian x87 long double stored in 16 bytes, as the existing guest long-double ABI does.

- Windows direct-memory backing reserves a paging-file section. A [direct memory page](../../../core/libs/prx/libc/include/WindowsMappings.hpp) mapped at one guest address is private write-watched memory at that address and is not committed in the section; a page mapped at a second address moves its whole resident run into the section (committed there) and every address becomes a view of it, tracked by write protection. An unmapped resident page that is not all zeros is kept in a private reservation until it is mapped again. Committed section contents remain across unmap/remap and are released when the backing and its remaining views are destroyed. A host import alias over part of a resident run is refused. Linux retains its existing backing. Peak gameplay memory and Windows versions other than the tested host remain unverified.
- [getc_unlocked, putc_unlocked, getchar_unlocked, putchar_unlocked](../../../core/libs/prx/libc/src/StandardStreams.cpp) (libc) - byte I/O uses the host unlocked operations; guest EOF/error flags and macro counters follow `FileStream`. Linux status queries use `feof_unlocked`/`ferror_unlocked` because [glibc `feof`](https://github.com/bminor/glibc/blob/d2097651cc57834dbfcaa102ddfacae0d86cfb66/libio/feof.c) and [`ferror`](https://github.com/bminor/glibc/blob/d2097651cc57834dbfcaa102ddfacae0d86cfb66/libio/ferror.c) can acquire the stream lock. Windows uses [the CRT no-lock byte operations](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/fgetc-nolock-fgetwc-nolock) and `feof`/`ferror`, verified under a held stream lock on UCRT. Console behavior and other host CRTs remain unverified.
- [fgetws, getwc, getwchar, putwc, putwchar](../../../core/libs/prx/libc/src/FormattingWide.cpp) (libc) - wide stream I/O encodes and decodes wide characters as UTF-8 on the underlying byte stream; `fgetws` reads characters into the destination buffer until newline or EOF and null-terminates, returning null on stream error. Console wide stream buffering and encoding details remain unverified.
- [ftrylockfile](../../../core/libs/prx/libc/src/RuntimeSupport.cpp) (libc) - tries the host CRT stream lock that `flockfile`, `funlockfile` and each locking host stdio call on the stream take, so it returns -1 while another thread holds the stream through `flockfile` or is inside such a call, and 0 when it acquires the lock or already owns it (recursively, released by as many `funlockfile` calls), as FreeBSD 11 [`_ftrylockfile`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libc/stdio/_flock_stub.c#L89-L104) does. A libc export holds the lock only for each host call it makes, not across several host calls or while it updates the guest `FILE` prefix. Linux uses glibc `ftrylockfile`. UCRT has no try variant of `_lock_file`, so Windows calls `TryEnterCriticalSection` on the `CRITICAL_SECTION` that `_lock_file` enters, found through the private UCRT stream layout (`__crt_stdio_stream_data` in `ucrt/inc/corecrt_internal_stdio.h`, unchanged from Windows SDK 10.0.19041 to 10.0.26100); another CRT or a change of that layout breaks it. A null or closed stream throws where FreeBSD dereferences it
- [Wide-character conversions](../../../core/libs/prx/libc/src/Multibyte.cpp) (libc) - The wide `wcsto*` functions parse the ASCII prefix of the guest string, as the C locale accepts only ASCII white space and digits. [`wcsrtombs`](../../../core/libs/prx/libc/src/Multibyte.cpp) uses the guest's single-byte C locale through `wcrtomb`; other encodings and shift states are not supported
- [realpath](../../../core/libs/prx/libc/src/RealPath.cpp) (libc) follows FreeBSD 11's [`realpath.c`](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/libc/stdlib/realpath.c) except for symlinks. - [sinhf](../../../core/libs/prx/libc/src/Math.cpp) (libc) follows the `sinhf` of the `libc.prx` bundled with PPSA28319 (disassembly): FreeBSD msun's [`e_sinhf.c`](https://github.com/freebsd/freebsd-src/blob/5aa554c7e5b6fd9042986df07f12ac5687e41392/lib/msun/src/e_sinhf.c) from before `__ldexp_expf`, which squares `expf(|x| / 2)` between `logf(FLT_MAX)` and the overflow threshold, calling msun's [`expm1f`](https://github.com/freebsd/freebsd-src/blob/59bc2f095289a10b8cfa55cbb2b45c3bd6c2d4ae/lib/msun/src/s_expm1f.c) and [`expf`](https://github.com/freebsd/freebsd-src/blob/59bc2f095289a10b8cfa55cbb2b45c3bd6c2d4ae/lib/msun/src/e_expf.c), whose paths for the arguments it passes are inlined here. Past the threshold Sony's error helper sets `errno` to `ERANGE` before returning `x * 1e37`; msun itself sets no `errno`. - [Complex functions](../../../core/libs/prx/libc/src/ComplexMath.cpp) (libc) - `cabs`, `carg`, `creal`, `cimag`, `conj`, `cproj`, `cacos`, `casin`, `catan`, `cacosh`, `casinh`, `catanh`, `ccos`, `csin`, `ctan`, `ccosh`, `csinh`, `ctanh`, `cexp`, `clog`, `csqrt`, `clog10` and `cpow` with their `f` and `l` forms take and return GCC complex types, so they keep the System V classes of C99 `_Complex` values (`long double` pairs passed in memory and returned in `st0`/`st1`), which on Windows relies on GCC's `sysv_abi` handling of complex types. The transcendental ones are computed by the host's math library, not by the console's FreeBSD msun `catrig.c`, `s_cexp.c` and `s_csqrt.c`, so results can differ in the last bits and in the sign of zero or NaN parts at branch cuts; errno is never set. `cpow` follows msun's [s_cpow.c](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/msun/src/s_cpow.c) (a zero base gives 0, otherwise polar form). FreeBSD 11 has no `clog10`: here its real part is `log10` of the magnitude and its imaginary part the argument scaled by 1/ln 10, as glibc computes it, falling back to the scaled `clog` when the magnitude overflows. Not compared with the console's `libc.prx`.
- [erf, erfc, tgamma, lgamma, lgamma_r, gamma, signgam, Bessel functions and missing float and long double forms](../../../core/libs/prx/libc/src/MathSpecial.cpp) (libc) - computed by the host's math library, as [acosl](../../../core/libs/prx/libc/src/Math.cpp) is, not by the console's FreeBSD msun code. `lgamma_r` and `lgammaf_r` report the sign of the gamma function as FreeBSD does (+1 at poles, the sign of a zero argument) and `lgamma`, `lgammaf` and `lgammal` store it in the guest `signgam`. `gamma` and `gammaf` are `lgamma` and `lgammaf`, as in FreeBSD. `j0f`, `j1f`, `jnf`, `y0f`, `y1f` and `ynf` round the host's double results, so they can differ from FreeBSD's float code in the last bit; on Windows the double ones are the CRT's `_j0` family. `nanl` ignores its tag, as `nan` and `nanf` do. `tgammal` and the other `long double` forms compute at full 80-bit precision, where FreeBSD 11 makes `tgammal` an alias of the double `tgamma`. errno is never set, as `math_errhandling` is `MATH_ERREXCEPT`. Not compared with the console's `libc.prx`.
- [Network address helpers](../../../core/libs/prx/libc/src/NetworkAddress.cpp) (libc) - `htonl`, `htons`, `ntohl`, `ntohs`, `inet_aton`, `inet_addr`, `inet_network`, `inet_lnaof`, `inet_netof`, `inet_makeaddr`, `inet_ntoa`, `inet_nsap_addr`, `inet_nsap_ntoa`, `ether_aton(_r)`, `ether_ntoa(_r)`, `ether_line`, the RFC 2292 `inet6_option_*` and the RFC 3542 `inet6_opt_*` and `inet6_rth_*` functions follow FreeBSD 11's `lib/libc/inet` and `lib/libc/net` ([inet_addr.c](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/libc/inet/inet_addr.c), [ether_addr.c](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/libc/net/ether_addr.c), [ip6opt.c](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/libc/net/ip6opt.c), [rthdr.c](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/libc/net/rthdr.c)) with the FreeBSD 11 `cmsghdr` (data at offset 16). `ether_line` and `ether_aton_r` parse with the host `sscanf`, which matches FreeBSD's in the C locale. The console has no `/etc/ethers`, so `ether_hostton` and `ether_ntohost` always return 1, as FreeBSD does when the file cannot be opened. Not compared with the console's `libc.prx` or `libSceNet`.
- [_WStoul](../../../core/libs/prx/libc/src/Strings.cpp), [_Iswctype](../../../core/libs/prx/libc/src/RuneLocale.cpp) and [swscanf_s, swscanf and vswscanf](../../../core/libs/prx/libc/src/ScanningWide.cpp) (libc) - `_WStoul` is `wcstoul` and throws for a base other than 0 or 2 to 36. `_Iswctype` takes the class numbers of Dinkumware's [xwcc.h](https://github.com/superna9999/ti-cgt6x/blob/cgt6x_7_3_4/include/xwcc.h) (1 `alnum` to 11 `xdigit`, 12 `blank`) and throws for any other value, including the FreeBSD masks `wctype` returns; the numbering is not confirmed on the console's `libc.prx`. `swscanf_s` follows C11 7.29.2.2 and K.3.9.1.5, but reads the size argument as `unsigned int` like `sscanf_s` where K.3.9.1.5 specifies `rsize_t`; the console's width is unverified. A runtime-constraint violation (null buffer, format or receiving pointer) only returns `EOF`, and a too small array gets a null first element as in `sscanf_s`. A literal mismatch is a matching failure and a field that is only a prefix, such as `0x` or `1e`, does not convert, as C11 requires; FreeBSD's `vfwscanf` reports an input failure for the first and converts the second. Integers out of range are truncated from `strtoll`/`strtoull`. It throws for `%p`, `%S`, `%C`, unknown length modifiers, scanset ranges, `%n` with suppression or width, and narrow `%s`, `%c` or `%[` input that the C-locale `wcrtomb` cannot convert. `swscanf` and `vswscanf` run the same scanner without the size arguments of `%s`, `%c` and `%[`, and with the same limits; a null receiving pointer throws.
- [regcomp, regexec, regerror, regfree](../../../core/libs/prx/libc/src/Regex.cpp) (libc) follow FreeBSD 11 [lib/libc/regex](https://github.com/freebsd/freebsd-src/tree/stable/11/lib/libc/regex) in the C locale: pattern and subject bytes are characters, `[:class:]` names, including the BSD `ideogram`, `special`, `phonogram`, `number` and `rune` of `wctype`, and `REG_ICASE` are ASCII only, bracket ranges compare byte values, and `[.name.]` accepts the names of `cname.h` or a single byte other than NUL. `REG_DUMP`, `REG_TRACE`, `REG_LARGE` and `REG_BACKR` are ignored. Multibyte characters and locale collation are not modelled. The matcher is not FreeBSD's: without back-references one forward pass over the subject keeps one state per pattern node, so finding the match takes time proportional to pattern size times subject length, and subexpressions are then assigned by FreeBSD's `dissect` rules. Compared with the FreeBSD sources built standalone on 4.3 million random patterns and subjects, overall matches, subexpressions, compile errors and `re_nsub` agree except in the cases below, including the matcher's quirks: adjacent anchors are applied in the order `^`/`$` then one `\<` or `\>` per position, limited by the number of `^` and `$` tokens, so `\<\<`, `\>$` and `$` repeated by `{2}` never match. The reference switches to a different representation above 64 states that can chain such anchors; here the 64-state behaviour is used for every size. A negative `rm_so` with `REG_STARTEND` is accepted as in FreeBSD, and the byte before offset 0 is then preceding text for `^`, `\<` and `\>`; FreeBSD treats offset 0 as the start of the text whenever one of its passes begins there, which depends on its must-string prescreen and its second pass, and then sometimes reads past `rm_eo`, crashes or loops: 83 of 133145 random cases with a negative `rm_so` differ. Patterns with back-references are first checked by a pass in which each back-reference stands for any text, then searched by exhaustive backtracking on an explicit stack for the longest match, taking the first path in preference order for ties; this can take exponential time on patterns that pass the check. FreeBSD instead runs `backref` over the region found by a pass in which each back-reference repeats its group's pattern, and 1274 of 22849 random patterns with back-references differ: an anchor or word boundary inside a referenced group stops FreeBSD matching (`\(^a\)\1` on `aa` does not match there and matches (0,2) here, likewise `\($\)\1` and `\(\<\)\1`), an optional or repeated group makes it miss matches (`\(a\)\{1,2\}\1` on `aa`) or report ones that skip the rest of the pattern (`\(^a\)\{0,1\}\1` on `a  ` gives (0,1) there and no match here), it can report a subexpression with `rm_eo` -1 (`\(.*a\{0,1\}\)\1*.*` on `a \n \naa` gives group 1 (0,-1) there and (0,7) here), and a back-reference to a group removed by `\{0\}` makes it fail with `REG_ASSERT` (`\(b\)\{0\}x*\1`) where here it compiles and the back-reference never matches. Repetitions that expand the pattern by more than 524288 elements in total, such as `((a{255}){255}){255}` or `(a{1,255}){1,255}` written many times, and groups nested 200 or more levels deep return `REG_ESPACE`, where FreeBSD compiles them. A null `regex_t`, pattern or subject crashes as in FreeBSD. `re_g` holds a host pointer.
