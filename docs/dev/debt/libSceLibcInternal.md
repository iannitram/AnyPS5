# libSceLibcInternal technical debt

### Unknown function info

- [_sceLibcInternalThreadAtexit, _sceLibcInternalThreadDtors](../../../core/libs/prx/libSceLibcInternal/Export.cpp) (libSceLibcInternal) - FreeBSD `__cxa_thread_atexit` semantics assumed; a null or non-image destructor and an allocation failure throw
- [_sceLibcInternalForceTlsDestructor](../../../core/libs/prx/libSceLibcInternal/Export.cpp) (libSceLibcInternal) - behaviour follows `sceLibcForceTlsDestructor(int)` in a title's `libc.prx` (disassembly): the calling thread's destructors whose dso belongs to the module run newest first, only if the dso's module is loaded and the dso points to itself, in up to 4 passes. The return type is unknown (that function returns nothing), 0 is returned. The module of each dso is looked up when the destructors are forced, not when they are registered as `libc.prx` does

### Functional

- [makecontext](../../../core/libs/prx/libSceLibcInternal/UserContext.cpp) (libSceLibcInternal) follows FreeBSD 11's `lib/libc/amd64/gen/makecontext.c`: at most six arguments, a stack of at least `MINSIGSTKSZ` (2048) bytes, and `exit(0)` when the function returns with no `uc_link`. The console's version is not verified
- [makecontext](../../../core/libs/prx/libSceLibcInternal/UserContext.cpp) (libSceLibcInternal) on Windows pins its stack writable until a later `makecontext` stack overlaps it, since nothing tells the library when the guest frees the stack
- [Thread exit destructors](../../../core/libs/prx/libSceLibcInternal/Export.cpp) (libSceLibcInternal) run when a libkernel thread finishes; on the main or a host thread only `_sceLibcInternalThreadDtors` runs them, as `exit` does, else they are dropped
- [fdopendir](../../../core/libs/prx/libSceLibcInternal/Directory.cpp) (libSceLibcInternal) - the directory stream starts at the directory's first entry, while FreeBSD's [`fdopendir`](https://github.com/freebsd/freebsd-src/blob/release/11.0.0/lib/libc/gen/opendir.c#L67-L74) reads from the descriptor's current offset, and `FD_CLOEXEC` is not set on the descriptor. As in FreeBSD, a descriptor that is not open fails with `EBADF`, one that is not a directory with `ENOTDIR` (both leave it open), and `closedir` closes it
- [fstatvfs](../../../core/libs/prx/libSceLibcInternal/FilesystemStatistics.cpp) (libSceLibcInternal) converts `_fstatfs` to the 88-byte `struct statvfs` as FreeBSD 9.2's `sfs2svfs` does (`f_bsize` from the transfer size, `f_frsize` from the block size, `f_favail` equal to `f_ffree`, `f_fsid` 0, `ST_RDONLY` and `ST_NOSUID` only). Differences: `f_namemax` is the `statfs` value, not `fpathconf(_PC_NAME_MAX)`; negative `f_bavail` and `f_ffree` wrap to unsigned without `EOVERFLOW`, as the same-width copy in FreeBSD does; inode counts are 0 on Windows, inherited from `_fstatfs`; a null output returns `EFAULT` after the descriptor is validated, where FreeBSD would fault. Layout and conversion are unverified against the PS5 library (PS5MC imports `fstatvfs` but was not run)
- [posix_spawn and posix_spawnp](../../../core/libs/prx/libSceLibcInternal/Spawn.cpp) (libSceLibcInternal) throw: creating a child process is not supported. PPSA99305 (Dusklight) and PPSA99309 (Wind Waker) stop on `main` at unresolved import `44hlATrd47U` (`posix_spawnattr_init`); a run with this PR has not established how far either title gets, and process creation still throws. The attribute and file action calls keep FreeBSD 11.4's objects, so a real `posix_spawn` would have to apply them in the child. Null or uninitialized objects, which FreeBSD dereferences, throw.
- [posix_spawnattr_getflags, posix_spawnattr_getpgroup, posix_spawnattr_getschedparam, posix_spawnattr_getschedpolicy, posix_spawnattr_getsigdefault, posix_spawnattr_getsigmask and their setters](../../../core/libs/prx/libSceLibcInternal/Spawn.cpp) (libSceLibcInternal) store and return the attribute fields as FreeBSD 11's [posix_spawn.c](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/libc/gen/posix_spawn.c) does, on the same attribute object as `posix_spawnattr_init`; the scheduling parameter is only the priority, and no value is validated. A null object or output pointer throws. Not compared with the console's `libc.prx`.
- [getopt, getopt_long](../../../core/libs/prx/libSceLibcInternal/Getopt.cpp) (libSceLibcInternal) follow FreeBSD 11 [getopt.c](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libc/stdlib/getopt.c) and [getopt_long.c](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libc/stdlib/getopt_long.c) with `GNU_COMPATIBLE`: `getopt` does not permute, `getopt_long` permutes unless `POSIXLY_CORRECT` is set in the guest environment or the option string starts with `+`, and the exported `opterr`, `optind`, `optopt`, `optreset` and `optarg` start at 1, 1, 0, 0 and null. Warnings go to the guest's current `stderr` prefixed with `__progname`, where FreeBSD's `warnx` keeps the `stderr` of its first call. A null `getopt` option string, a null argument vector or argument, a negative `optind` and an `optind` moved inside a pending permutation throw where FreeBSD faults. `getopt_long_only` is not exported. That the console's `libSceLibcInternal` uses this FreeBSD code is unverified
- [sys_siglist and sys_nsig](../../../core/libs/prx/libSceLibcInternal/SignalList.cpp) (libSceLibcInternal) hold the 32 descriptions and the count of [FreeBSD 11.4](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libc/gen/siglist.c#L73-L107) `siglist.c` (`NSIG` 32, signal 0 to `SIGUSR2`); the console's table was not read
- [getopt, getopt_long, getopt_long_only](../../../core/libs/prx/libSceLibcInternal/Getopt.cpp) (libSceLibcInternal) and `optarg`, `optind`, `opterr`, `optopt` and `optreset` follow FreeBSD 11's [getopt.c](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/libc/stdlib/getopt.c) and [getopt_long.c](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/libc/stdlib/getopt_long.c) built with `GNU_COMPATIBLE`, as FreeBSD builds it: `getopt` keeps its own scanning state, `getopt_long` permutes operands unless `POSIXLY_CORRECT` is set in the guest environment or the option string starts with `+`, and error messages are prefixed with `getprogname()`: `getopt_long` writes them with `warnx`, so to the file `err_set_file` chose, and `getopt` with `fprintf` to the guest `stderr`, as FreeBSD does. The console's `libc.prx` also has the static `getopt.place` that the PS4/PS5 symbol database lists, which matches FreeBSD's `getopt.c`; its messages and `POSIXLY_CORRECT` handling are not compared with the console.
- [err, errc, errx, warn, warnc, warnx and their v variants, err_set_file, err_set_exit](../../../core/libs/prx/libSceLibcInternal/ErrorReports.cpp) (libSceLibcInternal) follow FreeBSD 11's [err.c](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/libc/gen/err.c): `getprogname()`, the message, and the `strerror` text of `errno` (or the given code) are written through the guest `fprintf` to the guest `stderr` or the stream set with `err_set_file`, and the `err` functions call the `err_set_exit` hook before the guest `exit`. Not compared with the console's `libc.prx`.
- [dprintf, vdprintf](../../../core/libs/prx/libSceLibcInternal/DescriptorPrintf.cpp) (libSceLibcInternal) format with the guest `vsnprintf` and write the whole text through the guest `write`, where FreeBSD 11's [vdprintf.c](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/libc/stdio/vdprintf.c) streams it through an unbuffered `FILE`: a failed or zero-byte write returns -1 with the write's `errno` (`EBADF` for a closed descriptor) even when part of the text was written. FreeBSD's `EMFILE` for a descriptor above `SHRT_MAX` is not applied, as guest sockets are numbered from `0x10000000`. Not compared with the console's `libc.prx`.
- [ftok](../../../core/libs/prx/libSceLibcInternal/InterprocessKey.cpp) (libSceLibcInternal) follows FreeBSD 11's [ftok.c](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/libc/gen/ftok.c): the id in the top byte of an unsigned 32-bit key, the low byte of `st_dev` and the low 16 bits of `st_ino` from the guest `stat`, or -1 with its `errno`. The device and inode numbers are the host's as the guest `stat` reports them, so keys differ from the console's.
- [fts_open, fts_read, fts_children, fts_set, fts_close, fts_get_clientptr, fts_set_clientptr, fts_get_stream, ftw and nftw](../../../core/libs/prx/libSceLibcInternal/FileTreeWalk.cpp) (libSceLibcInternal) follow FreeBSD 11's [fts.c](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/libc/gen/fts.c), [ftw.c](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/libc/gen/ftw.c) and [nftw.c](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/libc/gen/nftw.c) with the FreeBSD 11 `FTS` and `FTSENT` layouts, reading guest paths through the guest `opendir`, `readdir`, `stat` and `lstat` and sorting through the guest `qsort`. Every walk runs as `FTS_NOCHDIR`, as FreeBSD does when it cannot open `.`: `fts_accpath` is the full path, the working directory never changes, and `nftw`'s `FTW_CHDIR` does not change into each directory before the callback. With `FTS_NOSTAT`, link counts are never trusted to skip `stat` calls (FreeBSD trusts them only on UFS, ZFS, NFS and ext2fs), so only the entry type from `readdir` avoids them. Whiteout entries are never reported. Not compared with the console's `libc.prx`.
- [glob and globfree](../../../core/libs/prx/libSceLibcInternal/Glob.cpp) (libSceLibcInternal) follow FreeBSD 11's [glob.c](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/libc/gen/glob.c) in the C locale: brace expansion, `GLOB_ALTDIRFUNC`, `GLOB_LIMIT` limits, `GLOB_NOCHECK` returning the original pattern, and sorting with the guest `strcoll`. Directories are read through the guest `opendir`, `readdir`, `lstat` and `stat`, so patterns name guest paths. The console has no password database, so `GLOB_TILDE` expands `~` from the guest `HOME` (unless `issetugid`), where FreeBSD falls back to `getpwuid`, and leaves `~` with `HOME` unset and `~user` unexpanded. Multibyte characters in patterns and names are taken byte by byte, as in the C locale. Not compared with the console's `libc.prx`.
